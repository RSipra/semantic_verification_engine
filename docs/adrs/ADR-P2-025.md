# ADR-P2-025: Tracer notebooks frozen as a stage snapshot (delinked from src)

**Status:**   ✅ Accepted (2026-11-03) — reverses the tracer part of 538a98dc <br>
**Phase:** P2


## Decision
Freeze the tracer demo notebooks and their support modules at the tracer stage (758da3b3).
They no longer depend on the src schema contract:
- tracer-era DTOs copied into `notebook_support/tracer_models_v0.py` (only edit: the import path `ds_utils` → `notebook_support`)
- `tracer_validation_v0` and `tracer_nlp_lab_v0` use the frozen DTOs and the `ds_constants` enums
- the runtime walkthrough is back to its tracer-era flow: load → hydrate → sample → `question_factory`
  (validation per question, no separate schema step)
- allowed changes: only those that keep the notebooks running (e.g. SDK migrations). No new features.

### Boundary assumption (frozen)
The tracer reflects the **pre-split** contract at 758da3b3. One Production DTO served as both:
- the offline handoff contract (what gets saved; tensors `Optional`), and
- the runtime object (tensors hydrated at session start, then validated by the same class).

Flow: Production DTO → parquet → df + tensor hydration → Production DTO validation (per question, in `question_factory`).
The frozen tracer takes **Production-DTO-validated data as its base assumption**.

## Options considered
1. **Keep the tracer on src** and bridge each drift (provenance backfill, null filling, `type: ignore` enum bridges)
2. **Keep the coupling, add a guard:** a CI smoke test that runs the tracer notebooks whenever src changes
3. **Freeze the tracer:** copy in the tracer-era DTOs and validator, and delink from src

## Selected option
Option 3 (freeze the tracer)

## Rationale
- The tracer records a *finished* stage, and the README makes its walkthrough step 3 of the repo review path, so it has to reproduce its documented results.
- 538a98dc (2026-05-17) moved the walkthrough onto src `core.enforce_schema` to unify validation. It worked at the time, because it came before the runtime split.
- Later src changes (d1925441 offline/runtime split; provenance fields in the generation DTOs) changed the shared contract, and the tracer broke **silently**: no test covered it as a consumer.
- Option 1: each fix added another bridge, a sign that the dependency boundary was in the wrong place.
- Option 2: an ongoing maintenance cost for a component that shouldn't change.

## Trade-offs
**Pros:**
- src schema changes can't break the tracer
- the notebooks reproduce the documented tracer results
- the lab code is simpler (no bridges or backfills)

**Cons:**
- duplicated DTO code (frozen copy vs. live src)
- the tracer is no longer a reference for current runtime behaviour

## Risks
- **Embedding model drift:** `core.embeddings` (the model loader) is still shared. The precomputed parquet embeddings
  assume the `sbert_settings` model is unchanged. A different model with the same 384 dims passes validation, but gives
  meaningless similarity scores.
- **Confusion:** the frozen `Production*` classes are the tracer-era *hydrated* schema, not today's offline
  `Production*`. The module docstrings say so.

## Consequences & Future considerations
- The tracer modules carry a "frozen, not runtime" scope note, and the old TODO
  ("use core.enforce_schema") is replaced with a note on this decision.
- Optional hardening: assert the SBERT model name when loading in the lab.
- If a later stage needs a new walkthrough, build it against the live src with its own tests. Don't extend the tracer.
- **Superseded in src by d1925441 (offline/runtime split):** Production DTO (offline, no tensors) → parquet →
  df + tensor hydration + runtime startup → **Runtime DTO** validation as the offline→runtime boundary check.
  The live boundary is in `src/core` (`enforce_schema` + Runtime DTOs). The tracer does not follow it.
- **Known shortcut (both stages):** Pydantic re-validation stands in for dedicated deserialization at the boundary
  (no declared storage schema or explicit record mapping). Acceptable at demo scale; revisit for larger datasets.
